# Публикация проекта MOTO EYE на GitHub

Этот пакет подготовлен как **самостоятельный Git-репозиторий**: у него есть README, структура документации, материалы проверки, вспомогательные скрипты, `.gitignore` и GitHub Actions. Создание удалённого репозитория и публикация не выполнялись автоматически.

## 1. Предпубликационная проверка

Перейдите в корневой каталог проекта и выполните:

```powershell
python .\tools\check_docs.py
Get-ChildItem -Recurse -File | Where-Object { $_.Extension -in '.img','.apk','.exe','.msi','.rar','.bin' }
```

Первый вызов проверяет локальные относительные ссылки и запрещённые бинарные артефакты в составе документации. Второй — дополнительный быстрый обзор наиболее рискованных расширений. Запуск Python-скрипта **не требует интернета**. Наличие исходных файлов изготовителя вне репозитория допустимо; они не должны попасть в коммит.

Перед открытой публикацией прочитайте [SECURITY.md](SECURITY.md) и [документ о лицензировании](docs/licensing.md). Убедитесь, что в репозитории нет необработанных UART/ADB логов с уникальными идентификаторами.

## 2. Первая публикация через Git

Установите Git for Windows, откройте PowerShell в каталоге проекта и выполните:

```powershell
git init
git branch -M main
git status
git add .
git diff --cached --stat
git commit -m "docs: establish Moto Eye A133 platform baseline"
```

Создайте на GitHub **пустой репозиторий** с именем, например, `moto-eye`. При создании не добавляйте новый README, `.gitignore` и LICENSE через сайт: они уже находятся в локальной структуре (лицензия будет выбрана отдельно).

```powershell
git remote add origin https://github.com/<USERNAME>/moto-eye.git
git push -u origin main
```

`<USERNAME>` заменяется именем собственного аккаунта; не вставляйте угловые скобки буквально. Для приватного репозитория выполните те же команды, выбрав Private при создании на сайте.

**Repository name:** `moto-eye`  
**Description:** `Research and development of an A133-based Android platform for a future motorcycle helmet HUD.`  
**Topics:** `embedded-systems`, `allwinner-a133`, `android`, `uart`, `adb`, `hardware-prototyping`, `helmet-hud`, `heads-up-display`.

Формулировка описывает исследование и разработку; она не утверждает наличие завершённого продукта или готового дисплея.

## 4. Работа с версиями

Рекомендуемые признаки выпусков:

- `v0.1.0` — зафиксированный работающий Android/ADB-стенд, доказательства и документация.
- `v0.2.0` — только после закрытия рисков питания и подтверждения длительной стабильности.
- `v0.3.0` — после успешного испытания реального видеовыхода.
- `v0.4.0` — после появления отдельного HUD-приложения.

Номера следующих выпусков — план, а не текущие теги. Создавайте тег только после проверки соответствующего состояния.

## 5. Принцип развития репозитория

Для каждого значимого изменения создавайте отдельную задачу (Issue) и коммит. Электрические схемы, метрики и решения должны сопровождаться доказательствами; изменения прикладной части — инструкциями сборки и испытаний. Закрепляйте проверенные образцы и версии ПО в `CHANGELOG.md`, но не публикуйте бинарные образы изготовителя без прав.

В `.github/workflows/docs-check.yml` настроена проверка ссылок и политики бинарных файлов. Дополнительная проверка синтаксиса PowerShell проводится в CI на Windows, но стендовые испытания USB/UART требуют реального оборудования и **не выполняются облачной CI автоматически**.
