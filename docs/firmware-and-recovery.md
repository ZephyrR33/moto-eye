# Заводская прошивка, FEL и восстановление программной среды

## 1. Состав исходного пакета

В архиве `REVB-A133资料`, полученном через Baidu Netdisk, были обнаружены документация аппаратной платформы, файлы конфигурации дисплеев, образы Android 10, утилиты PhoenixSuit и драйверы. Инженерная ценность пакета заключается в согласованности нескольких уровней: вариант SoM, конфигурация периферии, bootloader, ядро, device tree и Android-образ.

Пути отражают структуру архивной рабочей копии. Они не являются ссылками на публичные загрузки; файлы и их версии должны быть заново сверены в собственном комплекте производителя.

## 2. Подбор образа

В истории работ указана маркировка радиомодуля **AW869A** и выбранный архив `REVB-A133V2-HDMI720P-AW869A-202302.zip`. После распаковки использован образ `REVB-A133V2-HDMI720P-AW869A-202302.img`, указанный объём ≈958 МиБ. Первоначальная проверка целостности копии проводилась с использованием SHA-256, однако итоговый digest не сохранился в доступных записях.

Выбор HDMI720P относится к базовому восстановлению Android и не предопределяет интерфейс будущего дисплея. Для реального микродисплея может потребоваться иная экранная конфигурация, а иногда — другая сборка прошивки.

## 3. Загрузочные режимы

**Обычный режим:** SoC стартует через BOOT0, читает загрузочные данные из eMMC, передаёт управление U-Boot, затем ядру Linux и Android. Это подтверждено UART-логами.

**FEL:** низкоуровневый режим обслуживания SoC. В отдельных проверках хост видел устройство `VID 1F3A / PID EFE8`. Предыдущая история содержит рекомендации относительно специальной площадки загрузки, однако её назначение в текущем отчёте **не проверено независимым измерением**; поэтому конкретные действия с UBOOT-пином намеренно не предлагаются как универсальная инструкция.

**PhoenixSuit:** фирменный инструмент записи заводских образов, использованная версия **V1.0.7**. На Windows требовались совместимые USB-драйверы; старый установщик иногда конфликтовал с драйверной средой и режимами повышения прав.

## 4. Как проходили восстановительные работы

1. Найдены и распакованы компоненты заводского пакета.
2. Сверена версия модуля и выбран образ Android 10 под ранее идентифицированный вариант AW869A.
3. Подготовлен PhoenixSuit V1.0.7; установлены требуемые драйверы после устранения проблем установки.
4. Проверялись состояния USB: отсутствие устройства, ошибка дескриптора, режим FEL.
5. В PhoenixSuit был выбран подготовленный заводской `.img`.
6. В дальнейшем подтверждена успешная загрузка Android из eMMC и работа ADB. Архивный отчёт о самой операции прошивки не содержит полного итогового протокола PhoenixSuit.

**Важно:** этот раздел фиксирует историю исследования и принцип восстановления, а не предлагает слепо повторять запись eMMC. Перепрошивка потенциально удаляет данные и может менять загрузчик, таблицу разделов и среду восстановления. При рабочей системе с ADB не требуется выполнять её повторно.

## 5. Верификация после прошивки

Полезные контрольные признаки:

| Проверка | Ожидаемое наблюдение |
| --- | --- |
| BOOT0 | `DRAM simple test OK` |
| U-Boot | `Loading Environment from SUNXI_FLASH... OK` |
| Linux | `Kernel init done` |
| Android | `sys.boot_completed=1` |
| USB | `sys.usb.state=adb`, `adbd` running |
| PC | `adb devices -l` возвращает `device` |
| Graphical | `wm size` и валидный кадр `screencap` |

Повторное появление BOOT0, когда питание не отключалось, означает новый цикл низкоуровневой загрузки. Но причин сброса оно само по себе не раскрывает.

## 6. Принцип публикации

В GitHub хранятся тексты, безопасные диагностические инструменты и редактированные результаты. Не хранятся чужие прошивки, драйверы и пакеты PhoenixSuit — это материалы производителя с самостоятельными правами распространения. Их хеши, даты, версии и ссылки следует вести в приватном инвентаре, если потребуется строгая повторяемость.
